# [SKILL_D01] Role Mapping (体用用神与多场景角色精准定位)

## 核心职责
根据 `master_router` 传入的场景标签（`SCENE_*`），在后端传入的 JSON 盘面数据中，精准锁定“我方（日干）”、“对方/事态（时干）”及场景专属的“核心用神”。

## 逻辑规则要点

### 1. 多维度角色解构 (Entity Network Mapping)
拒绝单一的二维推导，必须根据场景自动提取并锁定**至少 4 个关联角色/要素**的落宫信息：
- **我方 (日干)**：代表自身的真实处境、筹码厚度、心态与承受力。
- **对方主体/老板/平台 (年干/值符)**：代表项目背后的操控者、大环境、大机构或对方公司的真实实力与信用底色。
- **引荐人/中间人/合伙人 (月干/六合)**：代表朋友、中介、同事的真实意图（是真诚相助还是拿回扣/拉垫背/被蒙在鼓里）。
- **事态表象/目标物 (时干)**：代表事情当前的表面迹象、发展趋势或直接交涉的标的。

### 2. 场景专属用神补充 (Scene-Specific Targets)
根据输入的 `SCENE_TAG`，在上述 4 大基础角色之外，强制叠加以下专属功能性用神：

- **`SCENE_WEALTH` (求财/投资/商业合作)**
  ➔ 聚焦 `生门` (代表利润、商业模式、造血能力)。
  ➔ 聚焦 `甲子戊` (代表资本金、现金流、核心预算)。

- **`SCENE_CAREER` (事业/跳槽/考公升迁)**
  ➔ 聚焦 `开门` (代表工作平台、公司架构、规章制度、法院)。
  ➔ 聚焦 `值符` (代表直属领导、大贵人、最高决策者、裁判官)。

- **`SCENE_LITIGATION` (官司/纠纷/危机公关)**
  ➔ 聚焦 `惊门` (代表诉讼、口舌、口水战、官非)。
  ➔ 聚焦 `景门` (代表证据、合同、文书、状纸、舆论)。
  ➔ 聚焦 `庚` (代表直接的对手、强大的阻力、仇人)。

- **`SCENE_RELATION` (感情/婚姻/合作人际)**
  ➔ 聚焦 `六合` (代表中介、婚姻关系、合作契约、团队黏性)。
  ➔ 聚焦 `乙` (代表女方) 与 `庚` (代表男方)。

- **`SCENE_ITEM_FOUND` (寻物/找失物/追逃)**
  ➔ 聚焦 `时干` (代表失物当前的所在地、物理状态)。
  ➔ 聚焦 `玄武` / `天蓬` (代表盗贼、遗失性质、隐匿状态)。

- **`SCENE_TARGET_DIAGNOSIS` (指定诊断与背调)**
  ➔ 聚焦 `指定的年命/天干/用神` (代表背调对象的真实实力与私下状态)。

- **`SCENE_DATE_SELECTION` (择吉/择方)**
  ➔ 聚焦 `吉门(开休生) / 三奇(乙丙丁) / 值符 / 驿马星` 降临的宫位（代表时空最佳的落地窗口与突围方向）。

- **`SCENE_HEALTH` (看病/健康/病灶定位)**
  ➔ 聚焦 `天芮星` (代表病灶本身、顽疾所在)。
  ➔ 聚焦 `乙奇` / `天心星` (代表中西医、主治医生、医药方案)。
  ➔ 聚焦 `死门` (代表病况的严重度、僵死状态)。

- **`SCENE_REAL_ESTATE` (买房/选宅/环境评估)**
  ➔ 聚焦 `生门` (代表房屋建筑本身、产物、阳宅)。
  ➔ 聚焦 `死门` (代表地基、周边风水环境、阴宅)。
  ➔ 聚焦 `值符` (代表产权归属、开发商背景、房屋品质)。

- **`SCENE_DECISION_CHOICE` (二选一/决策分叉)**
  ➔ 分别锁定对比选项 A 与选项 B 对应的特定天干/宫位，准备平行对比。

## 输出要求
在本阶段结束时，系统必须明确记录：
1. 主用神：日干落宫信息。
2. 客用神：时干落宫信息。
3. 场景核心用神：落宫信息。
